## What this is

A local, model-driven web app that turns US App Store reviews into
evidence-grounded product plans: enter a URL (or import JSON/CSV) + an analysis
goal, and it collects, cleans, dynamically classifies, finds problems, plans
versions, writes a PRD and test cases, then deterministically validates the
whole `review → finding → requirement → test` chain. Every run streams NDJSON
events and persists a file snapshot under `data/runs/<runId>/` (git-ignored)
that can be replayed offline as a **Cached Replay** (no network, no model).

## Architecture (the big picture)

The core contract is the **run event stream**: `POST /api/runs` returns an
NDJSON stream of `RunEvent`s, and every stage/artifact/limitation/failure is
pushed over it. The UI derives its entire state (stage rail, live progress,
loaded artifacts, provenance badge, terminal state) from these events plus
polling the artifact API. Persistence and streaming are coupled by design:
`EventPublisher` appends each event to `events.ndjson` **then** notifies stream
subscribers, so the on-disk log and the HTTP stream are byte-identical.

Layered data flow:

- **`src/app/api/runs/route.ts`** — the single entry point. Validates the
  request body against `RunStartRequestSchema`, then either starts a live
  analysis or replays a cached run. Errors before the stream starts are clean
  `application/problem+json`; errors after are terminal `run.failed` events.
  The response stream's `cancel()` aborts the underlying work via `req.signal`.
- **`src/server/pipeline/orchestrator.ts`** — `executeRun` drives the stage
  order `source → prepare → scope → topics → findings → planning → tests →
  traceability → (optional revision) → final-report`. It owns manifest
  lifecycle (a single running manifest at start, finalized at the end — never
  rewritten per-artifact, to avoid EPERM races on Windows). It also owns the
  *post-revision renormalization*: the revision stage's raw model output is fed
  through the same `normalizeFindings`/`normalizePlanningOutput`/`normalizeTestsOutput`
  used by the initial stages, and revised artifacts are published as
  attempt-02.
- **`src/server/pipeline/stages/*`** — one file per stage. Each takes a typed
  context (model client + inputs + `onProgress`) and returns a Zod-validated
  artifact. Model output is *never trusted*: evidence excerpts are verified as
  exact substrings of the cited review, sample counts and confidence are
  recomputed by code, and unsupported findings are dropped.
- **`src/server/model/`** — `OpenAiCompatibleClient.generate<T>()` is a minimal
  chat-completions adapter with bounded retries: transient failures (5xx,
  network errors, per-call timeouts) are retried up to `MAX_RETRIES` (2) with
  backoff; deterministic failures (4xx, schema/model-output errors) and client
  disconnects are not retried. Every call takes a Zod `schema` and is validated
  against it. The usage log aggregates model/calls/durations for the manifest
  but never the API key. `ScriptedModelClient` is the test double for
  integration tests.
- **`src/domain/`** — pure, deterministic functions with no I/O: contracts
  (Zod), review normalization/dedupe/stats, traceability validation. This is
  what "rules" means in the rules-vs-model split.
- **`src/server/sources/`** — Apple RSS collector (sequential, ≥500ms apart,
  max 10 pages; page-1 empties retried twice at 2s/5s, empty pages before
  `rel=last` confirmed once then `partial`, repeated pages detected before
  appending), JSON/CSV import parser, a per-app local review cache
  (`AppleReviewCacheStore`, `data/source-cache/`), and the preview service
  (`source-preview.ts`, snapshots under `data/source-previews/` with a 30-min
  TTL). An HTTP-200 empty feed is `suspect-empty`, never "no reviews".
- **`src/server/runs/`** — `RunStore` (file snapshot CRUD), `RunCatalog`,
  `Replay`. `data/runs/` is git-ignored; `fixtures/demo-runs/` ships a real,
  privacy-minimized capture.
- **`src/components/workbench/`** — client components. `workbench.tsx` owns
  artifact polling; `useRunStream` (in `src/hooks/`) owns NDJSON parsing.

## Key invariants to preserve

- **Live progress must survive long runs.** The frontend polls artifacts every
  800ms until a terminal `run.completed`/`run.failed` event arrives (then one
  final flush), *not* on an attempt ceiling — a real run took ~25min and a
  fixed ceiling silently dropped every late artifact. See the
  `workbench-long-run.test.tsx` regression test before touching that loop.
- **Topic discovery and consolidation are both size-bounded.** `topics.ts`
  chunks reviews by `CHUNK_CHAR_BUDGET` and runs discovery batches in parallel
  (`maxConcurrency`, default 3). Consolidation splits candidates into groups of
  `CONSOLIDATION_CANDIDATE_BUDGET` (15) and merges same-label groups by code —
  a single oversized consolidation call (~36KB input) was the recurring
  `MODEL_HTTP_ERROR: 500` source. If you see that 500 again, check which prompt
  version failed in the run manifest's `modelUsage.promptVersions`, then shrink
  the relevant budget.
- **Model key must never reach disk, logs, or the repo.** `OpenAiCompatibleClient`
  strips it from request snapshots; `config.ts` writes only `MODEL_*` values to
  git-ignored `.env.local` via the settings panel.
- **Traceability is deterministic and single-revision.** `validateTraceability`
  enforces the full invariant list; on failure exactly one constrained revision
  runs (may delete/fix/downgrade, never add citations), published as
  attempt-02. A second failure is an explicit `run.failed` with
  `TRACEABILITY_INVALID_AFTER_REVISION` — never a fabricated success.
- **The manifest is written once at start and finalized once at end.** Do not
  rewrite it per-artifact (Windows rename-over-open races with concurrent
  artifact reads → EPERM). Intermediate artifacts are read via attempt-1
  fallback in the artifact route.

## Model config

Configured via env (`.env.local`, git-ignored) or the UI Settings panel, which
writes to the same file. `MODEL_BASE_URL` + `MODEL_NAME` are required for the
model path; `MODEL_API_KEY` may be empty (local runtimes). Temperature is fixed
at 0.1. Without a model, the deterministic stages still run and the run
completes with a `MODEL_NOT_CONFIGURED` limitation; catalog and cached replay
always work. See `.env.example` and `docs/model-analysis.md`.
